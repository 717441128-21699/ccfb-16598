# 咕嘟酿酒观察站 / Airlock Brew Studio

手机放在发酵罐旁，用 Web Audio API 采集气塞声，在 `AudioWorklet` 中按帧识别每一声“咕嘟”，按声纹分离多个发酵罐，再由累计 CO₂ 推算产气速度、当前比重、酒精度和主发酵结束日。

这是一个**无后端、无账号、音频不出本机**的移动端优先 Web 应用。首次打开会载入三罐完整示范数据，可直接查看曲线、声纹、偏差面板和警报。

## 页面

- **罐子管理**：发酵罐、啤酒风格、酵母温度-速度表、体积、OG/FG、单泡体积修正、声纹状态；风格发酵过程可新建和编辑。
- **夜间监听**：
  - `getUserMedia` + Web Audio API 采集麦克风；
  - `AudioWorklet` 每 1024 个采样做 RMS、FFT 频谱、频带能量、平坦度、过零率和起振/衰减状态判定；
  - 排除压缩机/空调低频长鸣、说话式调制、狗叫/碰撞类宽带噪声；
  - 每个气塞训练主频、频宽、时长、衰减和频带比例，运行时用加权最近声纹分类；
  - 提供不依赖麦克风的“多罐演示声源”。
- **发酵曲线**：SG 推算线、比重计实测点、冒泡速率柱、预测峰期、主发酵结束标记、温度 +2 °C 峰期提前表、≤0.003 偏差验收和 CSV 导出。
- **酿造记录**：历史批次、ABV、笔记、比重计取样台账、JSON 备份、恢复示范/清空数据。

## 运行

```bash
npm install
npm run dev
```

Vite 已启用自签名 HTTPS。终端会输出 `https://<局域网IP>:5173/`，手机和电脑连同一 Wi-Fi，用手机打开该地址并信任一次自签名证书，浏览器才允许调用麦克风。

其他命令：

```bash
npm test          # 比重/峰期/声纹验收测试
npm run build     # tsc --noEmit + 生产构建
npm run preview   # 本地预览生产包
npm run smoke:audio
```

`npm run smoke:audio` 会在 Node VM 中直接加载真实的 `public/worklets/bubble-worklet.js`，喂入合成咕嘟声、低频轰鸣、宽带狗叫和说话式声音，检查 Worklet 判定结果。

## 关键模型

### 1. 气泡体积到 CO₂

Worklet 用 Minnaert 共鸣关系给出单个气泡的声学尺寸先验：

```text
r(mm) ≈ 3260 / f(Hz)
V(mL) = 4/3 · π · r(cm)^3
```

气塞和腔体 resonance 不等于自由气泡，因此每个罐子还有用户校准的平均 `bubbleVolumeMl`。事件体积会围绕该平均值按频谱估算的相对大小变化。

累计气泡体积按湿气体理想气体状态方程换算 CO₂ 质量，并扣除水蒸气压：

```text
n(CO₂) = (P − P_H₂O) · V / (R · T)
m(CO₂) = n · 44.0095 g/mol
```

### 2. CO₂ 到糖、酒精和 SG

发酵反应：

```text
C₆H₁₂O₆ → 2 C₂H₅OH + 2 CO₂
```

因此：

```text
m(乙醇) / m(CO₂) = 46.068 / 44.0095 ≈ 1.0468
m(被发酵糖) / m(CO₂) = 180.156 / (2 × 44.0095) ≈ 2.0467
```

由乙醇质量和批次体积得到 ABV，再用 Hall/Zymurgy 的 OG–ABV–SG 关系反解当前比重：

```text
ABV = 76.08 · (OG − SG) / (1.775 − OG) · SG / 0.794
```

比重计读数可反向计算该时刻理论 CO₂ 质量，并用稳健中位数拟合一个 `productionFactor`，吸收单泡体积误差、溶存 CO₂、漏检、漏气和气压误差。

### 3. 主发酵结束日

系统按开始时间切分发酵日，结合：

- 日冒泡速率降到峰值的 10% 以下；
- 次日仍保持低位；
- 推算 SG 的 24 h 变化 ≤ 0.0025，或已接近目标 FG；
- 比重计读数不与终点冲突。

验收 fixture 中，预测峰值在第 3 天，主发酵结束正确判为第 7 天；每日四舍五入到 0.001 SG 的比重计读数与累计产气推算值的最大偏差不超过 0.003 SG。运行 `npm test` 可复现。

> 真实厨房环境中，首次使用仍建议输入前 1–2 次比重计读数校准单泡体积/产气量修正。没有这个物理标定，任何声学 App 都无法知道一个气塞泡究竟是 0.2 mL 还是 2 mL。

### 4. 温度和峰期

内置酵母温度-速度表参考常见厂商资料的走势，并在表点之间线性插值；表外使用 Q10 外推。峰期时间与发酵速度成反比：

```text
peakHours(T) = peakAtRefHours · styleFactor · speed(Tref) / speed(T)
```

测试覆盖：

- 每种酵母表中，温度每升高 2 °C，峰期一定提前；
- 提前量严格等于速度表比值的倒数；
- US-05 型曲线在 20 → 22 °C 时约提前 6–7 小时，符合 Q10 ≈ 2 的常见走势；
- 拉格低温峰期明显晚于艾尔/小麦高温峰期。

内置美式 IPA、世涛、德式小麦、皮尔森/拉格和赛松五种风格；每种风格的温度、OG/FG、峰期系数和预期主发酵天数都可自行修改或新建。

## 警报

- **发酵停滞**：启动 24 h 后超过 6 h 无冒泡，且推算 SG 仍高于目标 FG + 0.004；超过 12 h 升为严重。
- **温度过高**：超过所选酵母表 `maxC` 为警告，超过上限 2 °C 为严重。
- **冒泡突然加快**：最近 15 分钟速率达到前 2 小时基线 2.5 倍且超过 30 声/小时；冷启动无基线时使用绝对阈值。
- 同一罐子、同一类型警报在 4 h 内不重复打扰。

## 数据与隐私

状态保存在浏览器 `localStorage`。默认**不保存麦克风录音**，只保存：

- 气泡/噪声判定事件（最近界面日志，内存中）；
- 每分钟或示范数据的计数与累计体积；
- 声纹统计特征；
- 比重计读数、罐子和酿造记录。

可在酿造记录页导出完整 JSON 或在曲线页导出 CSV。

## 手机整夜使用注意

- Android Chrome 效果通常最稳定；iOS Safari 对后台音频和屏幕锁定更严格，建议“添加到主屏幕”、接通电源并保持前台/屏幕常亮。
- 应用会在支持的浏览器中请求 Screen Wake Lock。
- 关闭回声消除、降噪和自动增益，避免系统把短促咕嘟当成噪声压制。
- 手机放在几个气塞中间，训练声纹时尽量保持手机和气塞位置不变。
